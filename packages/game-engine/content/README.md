# Сценарии игры

Основной технический сценарий лежит в `scenarios/technical-mvp.json`. Здесь можно менять тексты,
доступные ходы, события, численные эффекты и правила игры. После изменения проверьте файл:

```bash
pnpm scenario:validate packages/game-engine/content/scenarios/technical-mvp.json
```

Некорректный файл не запустится. Проверка ловит лишние поля, неизвестные этапы и свойства,
повторяющиеся идентификаторы, неправильные ссылки и расхождение числа раундов с `roundLimit`.

## Как устроен ход

В каждом раунде проходят два голосования:

1. Игроки выбирают этап из списка `rounds[].stageChoices`. В основном сценарии доступны все восемь.
2. Игроки выбирают действие из `actionIds` победившего этапа.

Сами действия лежат один раз в общем каталоге `stageActions`. Раунды только ссылаются на них по
стабильному идентификатору. Поэтому одно действие можно предлагать в нескольких раундах, а к уже
изменённому этапу можно вернуться и применить к нему другое действие.

У действия есть:

- `stage` — этап SDLC;
- `title`, `description`, `evidence` и `shortFeedback` — видимый текст;
- `effect` и `addProperties` — последствия для показателей и свойств процесса;
- `availableInStates` — состояния этапа, в которых действие доступно;
- `resultingStageState` — состояние этапа после решения;
- `repeatable` — можно ли применять то же действие повторно.

По умолчанию ставьте `repeatable: false`: повторяемое действие снова применяет свой численный
эффект. Если этап должен оставаться доступным всю игру, оставьте для него хотя бы одно осмысленное
повторяемое действие во всех трёх состояниях. Чтобы починить сломанный этап, разрешите действие в
состоянии `BROKEN` и задайте `resultingStageState: "AI_ENABLED"`. История уже применённых действий
сохраняется отдельно от текущего состояния этапа.

Поле `key` — короткая метка на карточке. У действий, которые могут оказаться в одном голосовании,
метки должны различаться. Порядок `actionIds` задаёт порядок карточек.

## События и накопленный контекст

`eventRules` проверяются сверху вниз. Последнее правило всегда безусловное и служит резервным.
Условия смотрят на состояние до применения текущего действия:

- `actionIds` — выбранное действие текущего раунда;
- `hasProperty` и `missingProperty` — свойства процесса;
- `hasAppliedActions` и `missingAppliedActions` — действия из предыдущих раундов;
- `appliedActionCount` — общее число предыдущих действий, границы задаются через `minimum` и
  `maximum`;
- `stageStates` — текущие состояния этапов;
- `stageActionCounts` — число предыдущих действий по конкретному этапу.

Все условия одного правила должны выполниться одновременно. Так события можно связывать с
предыдущими решениями, не перечисляя отдельную ветку для каждой комбинации.

## Остальная конфигурация

- `rules` — число раундов, пороги и условие победы;
- `mechanics.initialMetrics` — стартовые значения четырёх показателей;
- `mechanics.metricBounds` — нижняя и верхняя границы показателей;
- `mechanics.propertyEffects` — постоянные поправки приобретённых свойств процесса;
- `rounds[].title` и `rounds[].situation` — заголовок и ситуация раунда;
- `event.effect` и `event.stageChanges` — последствия выбранного события.

Допустимые показатели: `deliverySpeed`, `quality`, `controllability`, `teamCapacity`. Допустимые
свойства: `humanReview`, `automatedTests`, `currentContext`, `observability`, `rollback`. Допустимые
состояния этапа: `AS_IS`, `AI_ENABLED`, `BROKEN`.

`evidence: "FACT"` используйте только для проверенного наблюдения. Игровые допущения и
непроверенные последствия помечайте как `"SCENARIO"`.

## Как добавить ход или раунд

1. Добавьте действие в `stageActions` под новым стабильным идентификатором.
2. Укажите этот идентификатор в `actionIds` нужного этапа и раунда.
3. При необходимости добавьте условное событие перед резервным правилом.
4. Укажите нужные этапы в каждом раунде. В основном сценарии оставьте все восемь и проверьте, что
   они доступны даже после повторных решений.
5. Обновите `version` и запустите проверку сценария и узкие тесты движка.

## Новый сценарий

1. Скопируйте существующий JSON в новый файл в `scenarios`.
2. Задайте новый стабильный `id`, начните `version` с 1 и отредактируйте содержимое.
3. Проверьте файл командой `pnpm scenario:validate <путь>`.
4. Запустите API с абсолютным путём в `SCENARIO_PATH`.

```bash
SCENARIO_PATH="$PWD/packages/game-engine/content/scenarios/my-scenario.json" pnpm dev:api
```

В Docker файл можно подключить без пересборки образа:

```bash
docker run --rm -p 8787:8787 \
  -e SCENARIO_PATH=/config/scenario.json \
  -v "$PWD/my-scenario.json:/config/scenario.json:ro" \
  -v ai-sdlc-data:/data ai-sdlc-api
```

После изменения внешнего файла перезапустите API. Новые комнаты получат новый сценарий, а уже
созданные продолжат использовать сохранённый в SQLite снимок.
