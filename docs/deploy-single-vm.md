# Обновление одной виртуалки

Скрипт поднимает фронтенд и API на одной машине без Docker Compose. Фронтенд открывается по
обычному HTTP на порту `80`, API остаётся внутри Docker-сети, а SQLite хранится в постоянном томе
`ai-sdlc-data`.

## Запуск

Сначала от `root` обновите репозиторий, затем передайте скрипту только IP виртуалки:

```bash
cd /opt/AI-SDLC-Game
git pull --ff-only origin main
./scripts/update-vm.sh 203.0.113.10
```

Git и права пользователя остаются под вашим контролем: скрипт не делает `git pull` и не вызывает
`sudo`. Для первого запуска и следующих обновлений он выполнит:

1. сборку API и фронтенда;
2. создание Docker-сети и постоянного тома, если их ещё нет;
3. резервную копию SQLite из работающего API;
4. замену контейнеров;
5. проверку `http://127.0.0.1/health`.

Новые контейнеры запускаются с `--init` и `--restart unless-stopped`. Порт API `8787` наружу не
открывается. Скрипт не удаляет том `ai-sdlc-data`.

Резервные копии лежат в `/var/backups/ai-sdlc-game`. При первом запуске базы ещё нет, поэтому этот
шаг пропускается.

## Фирменные шрифты

Если файлы уже лежат в игнорируемой папке `apps/web/public/private-fonts`, скрипт подключит
`fonts.css` при сборке. Эта папка переживает `git pull` и не попадает в Git.

## Что нужно открыть

Откройте входящий TCP-порт `80` в firewall облака и виртуалки. После запуска приложение будет
доступно по адресу, который скрипт напечатает в конце.

## Если Docker пишет про zombie PID

Старый контейнер с zombie-процессом нельзя удалить обычным `docker rm -f`. Не удаляйте
`ai-sdlc-data` и не меняйте файлы в `/var/lib/docker`. Перезагрузите виртуалку или вручную
перезапустите Docker daemon, затем снова выполните ту же команду. `--init` нужен, чтобы эта ситуация
не повторялась с новыми контейнерами.

## Ограничения

Этот скрипт рассчитан на прямой доступ по IP, HTTP и порт `80`. Домен, HTTPS и внешний прокси лучше
добавить отдельно, когда они понадобятся.
