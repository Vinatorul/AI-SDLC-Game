# Обновление приложения на одной виртуалке

Скрипт запускает API и фронтенд без Docker Compose. Если передать домен, он также запускает Caddy.
Caddy сам получает и обновляет сертификат, перенаправляет HTTP на HTTPS и передаёт запросы
фронтенду. API остаётся внутри Docker-сети, а SQLite хранится в постоянном томе `ai-sdlc-data`.

## Перед первым запуском

Для домена:

- направьте его A-запись на виртуалку;
- откройте входящие TCP-порты `80` и `443` в firewall облака и виртуалки.

Для временного доступа по IP достаточно открыть TCP-порт `80`.

## Запуск

Сначала от `root` обновите репозиторий, затем передайте скрипту домен без схемы и пути:

```bash
cd /opt/AI-SDLC-Game
git pull --ff-only origin main

DOMAIN='game.example.com'
./scripts/update-vm.sh "$DOMAIN"
```

Скрипт не делает `git pull` и не вызывает `sudo`. Для следующих обновлений используйте ту же
команду. Скрипт выполнит:

1. сборку API и фронтенда;
2. для домена — подготовку и проверку Caddy;
3. резервную копию SQLite из работающего API;
4. замену контейнеров API, фронтенда и Caddy;
5. проверку `https://<домен>/health`.

Если API должен принимать запросы ещё от одного фронтенда, добавьте его origin через переменную:

```bash
EXTRA_CORS_ORIGINS='https://pages.example.com' ./scripts/update-vm.sh "$DOMAIN"
```

Новые контейнеры запускаются с `--init` и `--restart unless-stopped`. Порт API `8787` наружу не
открывается. Скрипт не удаляет том `ai-sdlc-data`. Сертификаты Caddy сохраняются в
`ai-sdlc-caddy-data` и переживают обновление контейнера.

Резервные копии лежат в `/var/backups/ai-sdlc-game`. При первом запуске базы ещё нет, поэтому этот
шаг пропускается.

## Фирменные шрифты

Если файлы уже лежат в игнорируемой папке `apps/web/public/private-fonts`, скрипт подключит
`fonts.css` при сборке. Эта папка переживает `git pull` и не попадает в Git.

## Проверка HTTPS

При первом запуске Caddy может несколько секунд получать сертификат. Проверить его состояние можно
так:

```bash
docker logs --tail 100 ai-sdlc-proxy
curl -fsS "https://${DOMAIN}/health"
```

Если в ответе есть `{"status":"ok"}`, приложение готово.

## Временный запуск по IP

Тот же скрипт сохраняет прежний HTTP-режим, если вместо домена передать IPv4-адрес:

```bash
./scripts/update-vm.sh 203.0.113.10
```

В этом режиме Caddy не запускается, а фронтенд занимает публичный порт `80`.

## Если Docker пишет про zombie PID

Старый контейнер с zombie-процессом нельзя удалить обычным `docker rm -f`. Не удаляйте
`ai-sdlc-data` и не меняйте файлы в `/var/lib/docker`. Перезагрузите виртуалку или вручную
перезапустите Docker daemon, затем снова выполните ту же команду. `--init` нужен, чтобы эта ситуация
не повторялась с новыми контейнерами.

## Ограничения

Скрипт рассчитан на один экземпляр API и постоянный Docker volume. Не удаляйте `ai-sdlc-data` и
не запускайте несколько API-контейнеров с одной SQLite.
