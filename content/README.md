# Контент и другие сеттинги

Сценарий — один JSON-файл: в нём названия и тексты, этапы, метрики, действия, зависимости,
события и правила победы. Для другого сеттинга не нужно менять движок или фронтенд.

- [technical-mvp.json](scenarios/technical-mvp.json) — основная игра про SDLC.
- [harbor-example.json](scenarios/harbor-example.json) — короткий пример про подготовку порта
  к шторму: три участка, три метрики и запасные детали вместо свойств процесса разработки.
- [Редактура SDLC-сценария](sdlc-authoring.md) — подробные правила текстов, последствий и ремонта.

## Что можно менять

| Поле | Что задаёт |
| --- | --- |
| `presentation.branding` | Название игры и текст главной страницы |
| `presentation.stages` | Идентификаторы, порядок и названия участков или этапов |
| `presentation.properties` | Идентификаторы и названия приобретённых свойств |
| `presentation.metricOrder` | Порядок метрик на экранах |
| `presentation.stageStateLabels` | Как называются исходное, готовое и сломанное состояния |
| `presentation.copy`, `outcomeLabels` | Подписи карты, сообщения о подготовке и тексты финала |
| `mechanics.initialStages` | Стартовое состояние каждого этапа |
| `mechanics.initialMetrics`, `metricDefinitions` | Набор метрик, стартовые баллы, названия и пояснения |
| `mechanics.metricBounds`, `rules` | Шкала, пороги, режим ходов и условие победы |
| `stageActions`, `rounds` | Варианты действий, вопросы, условия событий и последствия |

Наборы этапов и метрик должны совпадать во всех соответствующих полях. В условиях, эффектах и
подсказках можно ссылаться только на объявленные идентификаторы. Используйте короткие постоянные
идентификаторы латиницей, например `pier` или `fleet.refit`: игроки видят их названия, а не ключи.
Для переименования этапа меняйте его `label` в `presentation.stages`.

В текстовых шаблонах доступны `{stage}`, `{action}`, `{completedBy}`. Они подставляют название
этапа, устанавливаемого решения и действия, которое завершило подготовку. Остальной текст пишется
целиком в сценарии.

## Что остаётся общей механикой

Каждый ход по-прежнему состоит из выбора этапа, выбора действия, события и применения последствий.
События проверяются по порядку; все условия одного правила должны выполниться одновременно.
Последнее правило — безусловное. Зависимости могут учитывать прежние действия, свойства, состояния
этапов и порядок решений.

У этапа три состояния. В JSON сохранены прежние технические обозначения: `AS_IS` — исходное,
`AI_ENABLED` — подготовленное, `BROKEN` — сломанное. Они нужны для совместимости старых комнат;
`AI_ENABLED` не обязывает новый сеттинг быть про AI. В примере порта игроки видят «Готово к шторму».
`rules.minReadyStagesToWin` задаёт, сколько подготовленных этапов нужно для победы.

Все метрики направлены одинаково: больше — лучше. Шкала и пороги общие для метрик сценария;
шкала должна включать отрицательные и положительные значения. Стоимость или время поэтому стоит
выражать оценкой, где высокий балл означает лучший результат, а не сырым числом расходов или часов.
Отдельные шкалы, метрики с противоположными направлениями и новые виды победы потребуют изменения
общей механики — это не настройки нынешнего формата.

## Как подключить свой сценарий

1. Скопируйте `harbor-example.json` в новый файл внутри `content/scenarios`.
2. Задайте свой `id`, `version: 1`, оставьте `schemaVersion: 5` и отредактируйте поля.
3. Проверьте файл и прочитайте изменённые тексты вслух:

```bash
pnpm scenario:validate content/scenarios/my-game.json
pnpm copy:validate content/scenarios/my-game.json
```

4. Запустите API с этим файлом:

```bash
SCENARIO_PATH="$PWD/content/scenarios/my-game.json" pnpm dev:api
```

Второй терминал для фронтенда: `pnpm dev:web`. Если оба приложения уже работают, не запускайте
второй API на том же порту: сначала остановите прежний процесс. В Docker внешний JSON по-прежнему
можно подключить read-only томом и указать его путь в `SCENARIO_PATH`.

После изменения файла перезапустите API и создайте новую комнату. Старые комнаты сохраняют свои
тексты, метрики и правила. Один API обслуживает один активный сценарий для новых комнат; выбор
сценария в интерфейсе пока не предусмотрен. Без `SCENARIO_PATH` запускается SDLC-сценарий.

Старые внешние файлы формата 4 поддерживаются как SDLC-сценарии. `legacy-presentation.json`
сохраняет прежние названия для таких файлов и комнат; не используйте его для настройки новой игры.
